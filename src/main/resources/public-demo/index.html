All counts and credit above are computed from this workspace’s accepted backend events, not seeded dashboard results. Arrival order and processing time are real requests; receive timestamps are simulated by the guided scenario.

What this mode demonstrates: the production attribution rules, event-time windows, first-write-wins event IDs, duplicate conversion protection, and late-touch correction. Requests are processed synchronously in this Java process. The guided scenario supplies server-validated synthetic receive timestamps to model delayed processing without waiting days. The full distributed project separately uses Kafka and PostgreSQL; this free demo does not connect to either.
